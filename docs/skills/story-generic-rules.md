# Story Generic Rules

本文件记录所有题材共用的故事结构规则。

## 初始规则

- 关键选择不能只改数值，必须考虑后续叙事影响
- 随机性只能在预制结果之间分配
- 单节点的直接候选结果不宜超过 3 个
- 关键历史标记在后文至少回响 2 次
- 单节点条件引用控制在 2 到 3 条
- 章节设计优先“分支后回收”，避免纯树膨胀
- 结局必须能回溯到玩家可感知的路线差异
- 首册节点正文尽量控制在小游戏友好的短文本范围内
- 每条终局路线都必须有显式候选结局池，不能依赖通用兜底
- 每次补完一章后，都要跑结构校验和随机模拟
- 首个可玩版优先保证单屏内可读可点，尽量避免引入滚动依赖
- 关键风险路线要有真实失败结果，否则宫斗体验会失去张力
- 首册交互页建议控制为：状态区 + 一段正文卡片 + 2 到 3 个选项卡片
- 主剧情节点默认使用“承接层 + 临场层 + 压力层”写法
- 关键选择默认补 `textAfterChoice`，避免节点之间只剩硬跳转
- 文案优化时，除了改内容本身，也要同步回头修正文案模板
- 评分系统要定期校准，避免大量路线默认落到 `S`

## 后续维护方式

每次迭代后，把可复用经验写成新规则，避免同类问题重复出现。
